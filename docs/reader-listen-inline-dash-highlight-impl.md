# 听书句中横线与高亮匹配（实现思路）

> **状态**：已采纳  
> **关联文件**：`src/utils/listen-text.ts`  
> **来源会话**：[听书切句与起播](c3f8bd51-ec80-47b8-be74-2f558038843f)  
> **相关文档**：[句级高亮](./reader-listen-highlight-impl.md)

---

## 1. 需求背景（必填）

正文对话里出现 `-----` 等句中横线时，听书高亮找不到对应 HTML，整句无法高亮。根因是 `stripMarkdownForTts` 把**任意**连续 3 个以上横线当装饰线清掉，导致 needle 与正文不一致。

成功标准：句中 `-----` 保留；整行分隔线仍去掉；`findPlainRangeInHtml` 能命中。

---

## 2. 用户需求与 Agent 问答（必填）

### 2.1 含 ----- 的句子无法高亮

**用户：**

> 加入一段话中包含了“---”这样的内容时……播放高亮会不正常，无法将内容进行高亮

**Agent 回答摘要（已落地）：**

- 去掉全局 `[-—]{3,}` 替换
- 仅用整行正则清除装饰分隔线
- 自检：`listen-strip-dashes.selfcheck.ts`

---

## 3. 实现思路（必填）

### 3.1 总体策略

TTS/听书坐标系必须与可在 HTML 中搜到的纯文本一致。装饰线只删「独占一行」的，不动句内省略号式横线。

---

## 4. 改动点对比：改前 / 改后（必填）

### 4.1 改动点：`stripMarkdownForTts` 横线规则

- **位置**：`src/utils/listen-text.ts` → `stripMarkdownForTts`
- **差异摘要**：句中横线保留，高亮可匹配。

#### 改动前

```ts
// 网文装饰分隔线——会误伤句中 -----
.replace(/[*＊]{3,}/g, " ")
// 任意位置 3 连横线变空格
.replace(/[-—_=~～]{3,}/g, " ")
.replace(/[·•.]{3,}/g, " ")
```

#### 改动后

```ts
// 仅清「整行」装饰分隔线；勿动句中的 -----
.replace(/^[ \t]*[*＊\-—_=~～·•.]{3,}[ \t]*$/gm, "")
// * * * 整行间隔星号分隔
.replace(/^[ \t]*(?:\*[ \t]*){2,}\*[ \t]*$/gm, "")
```
